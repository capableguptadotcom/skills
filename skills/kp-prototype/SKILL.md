name: kp-prototype
description: Build a disposable experiment to answer one design or behavior question with observable results. Use when a prototype is requested or one bounded uncertainty needs an executable check.
---

# Answer one question

State the uncertainty, cheapest experiment, and observation that would favor each option. Use a scratch directory or the project's established prototype location; keep the experiment separate from production paths.

Implement only enough to test the question. Use representative data and disclose mocks or simplifications that affect the conclusion. Reuse available tooling instead of building a new harness without need.

Run it, inspect the result, and report the decision it supports and what remains unknown. A prototype is not production readiness. Do not promote it, deploy it, or expand scope without that work being requested.

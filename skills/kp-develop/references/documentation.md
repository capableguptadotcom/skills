# Document the implemented behavior

Identify the reader and the task or decision the document supports. Inspect the implementation, runnable commands and existing documentation structure. Update the established home instead of creating a parallel manual.

Explain relevant behavior, prerequisites, examples and limitations. Mark proposed behavior as proposed. Verify commands where practical and check links, names and exact technical values.

For an approved consequential decision, preserve its meaning and use the project's ADR location and filename convention. Record context, alternatives and consequences only when supported by the decision; do not invent rationale. Keep credentials, private transcripts and unnecessary personal paths out of shared examples.

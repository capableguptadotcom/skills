# Review the actual interface

Establish the user, task, device, and relevant states. Inspect screenshots or the running interface before judging it. If access is unavailable, state that limitation and keep code-based observations distinct from observed behavior.

Trace the user's primary action and important failure/recovery states. Check hierarchy, labels, keyboard operation, focus, contrast with a measuring tool when needed, responsive behavior, and motion alternatives. Apply the product's existing design system before personal taste.

For each finding describe the observed state, user consequence, and smallest useful correction. Separate a broken interaction or measurable accessibility issue from a design preference. A static mockup does not prove loading and error states can be removed.

Report evidence and coverage. A critique request does not authorize implementation or sharing screenshots outside the requested destination.

# Assess the actual interface

Establish the user, task, device and relevant states. Inspect screenshots or the running interface before judging it. If access is unavailable, distinguish code observations from rendered evidence. Use native product/design tools when available; this reference does not install or provide them.

Trace the primary action and important failure/recovery states. Check hierarchy, labels, keyboard operation, focus, responsive behavior and motion alternatives against the existing design system. Use a measurement tool for factual contrast claims instead of estimating from an image.

Tie a finding to an observed state and a user consequence. Separate defects and measurable accessibility issues from preferences. A static mockup does not justify deleting loading/error behavior. Recommend the smallest useful correction and state coverage gaps. An assessment request alone does not authorize edits or external image uploads.
